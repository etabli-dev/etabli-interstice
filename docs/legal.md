# Licensing, independent implementation and clearance

Recorded 2026-11-26. This is a project risk record, not a legal clearance opinion or guarantee against claims.

## License choice

Use the unmodified **GNU Affero General Public License version 3 only**, SPDX `AGPL-3.0-only`. This is a strong reciprocal open-source choice for network software. It permits commercial use. Covered modifications used interactively over a network trigger the source-offer provision in section 13; distribution has additional source and notice obligations. It does not automatically relicense every independent service on the same host.

Do not append noncommercial, no-hosting, approved-users-only or no-competition restrictions. Those would conflict with the intended open-source model. The license cannot prevent every commercial competitor; its purpose here is reciprocity. Trademark protection is separate and must not remove software freedoms.

Sources: [GNU AGPL text](https://www.gnu.org/licenses/agpl-3.0.html), [OSI definition](https://opensource.org/osd), [OSI licensing FAQ](https://opensource.org/faq).

## Independent product development

The product is specified from scheduling needs, public standards and public capability descriptions. No proprietary source code, bundled client code, artwork, screenshots or copied help text is included. Do not reproduce another product's visual identity, screen composition, wording or implementation. Keep implementation provenance and license records for all incorporated material.

The [CJEU account of C-406/10](https://curia.europa.eu/site/upload/docs/application/pdf/2012-05/cp120053en.pdf) distinguishes program functionality from protected expression. This does not give blanket clearance for copied documentation, graphics, contractual violations, confidential information or patents. Publicly observable functionality is not a guarantee of freedom to operate.

FlowSavvy appears only as a factual capability benchmark and migration origin. Interstice is not affiliated with, endorsed by or a version of FlowSavvy. Do not use its logos, distinctive marketing copy or name in the product name, domain or container image name. Future comparisons must be accurate, dated and based on verified behavior; never advertise complete parity before testing it.

Migration must use the owner's authorized exports or documented interfaces within applicable terms. This concept does not authorize scraping private endpoints, bypassing restrictions or copying proprietary assets. A compatibility adapter must be independently written and tested against permitted contracts.

## Name screening

Working name: **Établi Interstice**, repository slug `etabli-interstice`. Preliminary web searches of the exact compound and slug found no obvious exact product match. The word Interstice is already used by unrelated software and businesses. This is a limited screening result, not exclusivity or trademark clearance.

Before a branded production launch, assess confusingly similar names, relevant software/service classes, markets and earlier rights through DPMA, EUIPO and WIPO, with specialist review where appropriate. Search-engine absence and GitHub availability are insufficient. See [DPMA search guidance](https://www.dpma.de/en/ip-search/search-for-ip-rights/search-for-trade-marks). Patent/freedom-to-operate review and service-term review remain outstanding; neither was completed by this concept work.

## Container compliance

Review every actual dependency and base image before release. Preserve notices; identify incompatible components; publish corresponding source and reproducible build inputs for covered components. Do not assume that placing software in separate containers settles whether a combined work exists.

The initial test runtime includes original code and a container build. Dependency license metadata is recorded separately; no comprehensive license opinion, proprietary implementation comparison, trademark-register clearance or patent clearance is claimed. Public distribution of built images must include corresponding-source arrangements for covered third-party components as well as this project's own source.
